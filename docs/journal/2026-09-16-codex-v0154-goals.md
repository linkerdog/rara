# Codex 0.154 Goal Lifecycle Alignment

## Scope

Align RARA's model-facing goal tools and local `/goal` controls with the
Codex 0.154 goal contract. This replaces RARA's independent goal-completion
classifier rather than adding another completion path.

## What Changed

- Added `Blocked` to the restored goal lifecycle and compact TUI presentation.
- Made `update_goal` accept `complete` and `blocked`; its instructions carry
  Codex's three-consecutive-turn repeated-blocker guard.
- Allowed `create_goal` and `/goal <objective>` to replace completed goals,
  while unfinished goals still reject replacement.
- Allowed `/goal resume` to resume blocked goals and state that the blocker
  audit restarts.
- Removed the evaluator module, evaluator-only `condition` state, injected
  evaluator reasons, and evaluator-driven completion branch.
- Recognized every lifecycle status during session restoration, including
  `Blocked` and `BudgetLimited`.

## Why

Codex makes the agent's explicit `update_goal` call authoritative. RARA's
secondary classifier could stop a goal after a different model decision, even
when the main agent had not completed the objective. Keeping one authoritative
tool lifecycle makes continuation predictable and avoids a provider-dependent
completion side channel.

## Trade-Offs

RARA does not persist a separate blocker-attempt counter. That mirrors Codex:
the threshold is part of the model-visible tool contract, and a resumed blocked
goal begins a fresh audit by instruction. This keeps the runtime small, but it
relies on agent compliance rather than independently verifying the count.

## Validation

- `cargo fmt --all`
- `cargo test tools::goal::tests`
- `cargo test goal_command_`
- `cargo test pursuing_goal_continues_without_a_hidden_completion_classifier`

## Follow-Up

No follow-up is required for this alignment. Provider behavior around the
blocked-state instruction should be observed through normal runtime telemetry.
